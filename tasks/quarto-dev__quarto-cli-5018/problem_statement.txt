### Issue #5011

#### Comment at 2023-03-29T03:39:27Z

Let's talk about this live tomorrow.

The issue is the presence of `filename="/etc/rstudio/rsession.conf"`. That causes us to attempt to render the code block as a listing, so that we can do the caption treatment on it.

In 1.2, we'd render the code block by itself like this:

![image](assets/quarto-dev__quarto-cli-5018/001.png)

In 1.3, we render the code block by itself like this:

![image](assets/quarto-dev__quarto-cli-5018/002.png)

I did this by design, but only because I didn't consider that people would want to put a listing inside a callout.

I think the new appearance is better, but I agree that we should have a way to disable this treatment since LaTeX callouts are necessarily relatively limited in functionality.

#### Comment at 2023-03-29T03:41:56Z

Without the filename attribute, we render successfully in 1.3:

![image](assets/quarto-dev__quarto-cli-5018/003.png)

This suggests a workaround: move `/etc/rstudio/rsession.conf` to outside the listing (and filename declaration), and into plain markdown content before the code block, `**/etc/rstudio/rsession.conf**`:

````
---
title: Hello
format: pdf
---

::: {.callout-note}
If the `www-frame-origin` option is set to `same` or `any` instead of a URI, you must add the following setting with the actual URI:

**/etc/rstudio/rsession.conf**

```{.ini}
tutorial-api-client-origin=http://localhost:8080
```
:::
````
