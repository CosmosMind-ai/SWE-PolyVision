### Current Behavior

Short report:
> When a document contains special Markdown formatting such as inline code, LaTeX/math, and pipe-containing expressions inside table cells, `documents.info` and `documents.update` may not be fully round-trip safe.
Re-importing exported Markdown can change formatting, split table rows, leak content outside the table, or truncate the original content. The API export does not always appear to be a reliable re-import payload for the same document.

## OBSERVED BEHAVIOR
The problematic cases seem to appear when Markdown combines:

- table cells
- inline code formatting such as `` `...` ``
- LaTeX/math blocks such as `$$...$$`
- special characters such as `|`, `_`, `{`, `}`, and backticks

Examples of failure modes observed through the API:

1. A table cell containing expressions such as `` `|Clock_NTP_Camera1 - Clock_GPS_Camera1|` `` is not preserved exactly after API import/export.
2. Math content containing pipe characters may be exported in one Markdown shape and then re-imported into a different internal structure.
3. Re-importing Markdown through `documents.update` can split one logical table row into multiple fragments.
4. Content that should stay inside a table cell can appear outside the table after re-import.
5. Exact Markdown formatting is not preserved, even when the logical content is intended to remain unchanged.

This seems especially relevant for technical documentation using:

- formulas
- code-like expressions
- identifiers with underscores/braces
- pipe-delimited expressions
- tables combining prose and notation

### Expected Behavior

Ideally, the following would hold:

1. `documents.info` would return Markdown that can be sent back through `documents.update` without changing the document structure unexpectedly.
2. If Outline intentionally normalizes Markdown, that normalization would still preserve the exact document structure and content boundaries.
3. Special formatting inside table cells would remain stable and would not truncate content, split rows, or leak nodes outside the table.

### Steps To Reproduce

Use a document containing a Markdown table with a cell that mixes prose and special formatting.

Example input:

```md
| Condition | Facts |
| --- | --- |
| Absolute time difference | The system checks `|Clock_NTP_Camera1 - Clock_GPS_Camera1|` and `|Clock_NTP_Camera2 - Clock_GPS_Camera2|`. |
```

Then:
1. create or update the document through `documents.update`
2. fetch it with `documents.info`
3. send the fetched Markdown back again through `documents.update`
4. fetch it once more

Observed result:

- the exported Markdown may no longer match the original input
- replaying the exported Markdown may further alter the document
- the table cell may be truncated or structurally split

## IMPACT
This makes reliable external tooling much harder for clients that sync Markdown to Outline through the public API.

Hello Tom,
Sorry to bother you again with that, but I believe that I have "nailed" down the "Table/LaTex" issue.
This is, I believe important as this situation breaks a simple .md API export, even rendered in a regular GitHub flavoured md renderer.
This has nothing to do with round-trip here.

Here is the breakdown:
A LaTex formula entered in Outline is automatically outputted via API in its **DISPLAY** form e.g.
 $|Clock_{NTP_{Camera1}} - Clock_{GPS_{Camera1}}|$ ->
```
$$
|Clock_{NTP_{Camera1}} - Clock_{GPS_{Camera1}}|
$$
```
The issue is that this form is not valid in a table as encoding must follow these rules:
-) Formulas must be encoded **INLINE**: `$$....$$` -> `$....$`;
-) Because of INLINE, the `$` must directly surround the formula;
-) Pipe character must be escaped (only in tables)

Exemple:

![Image](assets/outline__outline-12569/005.png)

Comes out as:
```
| Excessive absolute difference between primary and secondary time references | $$
|Clock_{NTP_{Camera1}} - Clock_{GPS_{Camera1}}|
$$The system checks `\|Clock_NTP_Camera1 - Clock_GPS_Camera1\|` and `\|Clock_NTP_Camera2 - Clock_GPS_Camera2\|`. If either value exceeds `Time_difference_treshold`, the candidate is rejected. The default value of `Time_difference_treshold` is **1000 ms**. |
```
Which doesn't show correctly in VSCode:
